## Втори проход (от c0c96122)

### Диагноза (сурова Lighthouse следа, мобилен режим)
- LCP елементът е фоновият постер на Hero; 92% от LCP е „render delay“: Hero е в мързелив `HomeSections` зад skeleton, а prerender HTML беше crawler заместител, който `createRoot` изтрива.
- Реално приложено забавяне (`--throttling-method=devtools`) показа: блокиращият CSS (35 KB) и 10 шрифта се борят за трафик с JS модулите; първоначалният React render е една дълга задача (~450 ms при 4x CPU).

### Промени
- `Index.tsx`: `HomeSections` (с Hero) се импортира директно; секциите под Hero остават мързеливи.
- `scripts/prerender.ts` + `scripts/generated/home-shell.html` (`scripts/perf/capture-home-shell.py`): `/` съдържа истинските Header + Hero (същото h1, CTA „Започнете безплатно“, бадж „Тестов период“, същия srcset); без видео и без сесийно състояние. Тест `src/test/homeShell.test.ts`.
- Само за `/`: CSS се вгражда в HTML (`data-inline-css`); другите страници ползват кеширания файл.
- `main.tsx`: първият render е в `startTransition` — React отстъпва нишката, вече нарисуваният shell остава до commit.
- Нов `hero-poster-720.webp` (7,7 KB) за телефони.
- `LazyOnVisible`: резерви телефон/таблет/desktop чрез CSS media queries (реагират на resize), задържани докато Suspense skeleton изчезне; `hashchange` и `scrollToHash` монтират всички чакащи секции.
- Header: бутон „Профил“ 44 px, под 640 px е само в долната навигация (без дублиране и колизия). Footer правни връзки 44 px.
