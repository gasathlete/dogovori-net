## Product options (proposals, NOT approved launch pricing)

1. **Free:** the existing public blank forms. This path already exists.
2. **Proposed 2.99 EUR:** one vetted static document plus instructions.
3. **Proposed 6.99 EUR:** a vetted themed bundle, such as rental plus a handover protocol, or a service agreement plus an NDA.

These need no user uploads and no AI. Before any sale, all of the following are required:
- server-verified, immutable catalog delivery (content hash per version, bound to the purchase);
- signed legal content acceptance for every sold version;
- consumer, account, payment, refund and withdrawal tests in the sandbox;
- a verified paid Stripe webhook for the exact product, amount and user (per the project payment rules).

There will be no paid subscription until recurring delivered value exists. No prices or checkout have been implemented for these options.

## Delivery map (source audit)

| Path | What it delivers | Safe for sale? |
|---|---|---|
| `/catalog`, `/shablon/:slug` | Public catalog pages built from `src/data/catalog*` | Free browsing only. There is no purchase binding. |
| `public/lead-magnets/*.pdf` (2 files) | Static free PDFs | Free only. They are not versioned for sale. |
| `download-blank` (Wizard) | AI-generated or cached blank | No. It is gated by `isNewProcessingOpen('download_blank')` and uses AI or cache, not an immutable catalog. |
| `download-document` | Saves a browser-supplied payload (any `kind`) | No. The new-content write gate is closed for all kinds. It must not be used for static sales. |

### Minimum missing delivery work (without opening any guard)
- An immutable catalog store: an asset per version with a SHA-256 hash, written only by a trusted service. No browser payload.
- A server delivery endpoint that serves only catalog assets bound to a verified entitlement (user, product, version, hash). It must never accept content from the request.
- A legal acceptance record per asset version, and a way to withdraw a version.
- Entitlement rows created only by the verified webhook. Refunds revoke access.
- Tests for each of the above, including a forged `kind` or payload and a tampered hash.
