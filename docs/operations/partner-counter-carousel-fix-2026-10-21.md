# Брояч и карусела на партньорите — поправка 21.10.2026

## Причини
- RPC `get_registered_users_count` работи на живо (HTTP 200, стойност 306 при проверката). Броячът изчезваше напълно при всяка грешка (`retry:false`, грешка скрива дори кеширани данни), а `Number(null)` можеше да стане 0. Долният ред също се показваше само при успех → нестабилен layout.
- Каруселата пренареждаше всички слайдове след всеки ход с ключове `id-position` → преизграждане на изображенията, lazy decode мигане; `transitionend` от дъщерни елементи се приемаше; `mouseenter` на телефон можеше да спре въртенето трайно.

## Поправка
- `SocialProofStrip.tsx`: редът „регистрирани потребители“ е винаги видим (skeleton → число → „—“ + „Опитайте отново“); 2 ограничени повторни опита; кешираните валидни данни остават при неуспешно опресняване; null/празно се отхвърля. Текстът вече не твърди, че всички потребители са фирми.
- `PartnerCarousel.tsx`: стабилен track [опашни копия][оригинали][начални копия] със стабилни ключове; мести се само `translate3d`, 900 ms ease, 3.5 s пауза; нормализация само на границата (визуално идентичен кадър). Eager изображения (≤24). Пауза при hover само за не-touch указател, при фокус само от клавиатура. Брояч „N / общо“.

## Проверка (реален браузър, живи данни)
- 390 px touch: 306 видими; 2+ пълни цикъла `1/4→4/4→1/4…`; DOM изображенията същите възли, 0 счупени, 0 layout shift; единственият скок е невидимата нормализация на границата; докосването не спира въртенето.
- 1280 px: 4 лога < 6 места → статичен ред, без бутони.
- Reduced motion: без автоматично въртене.
- Тестове: `partnerCarousel.test.tsx`, `socialProofCounter.test.tsx` — 13/13 (грешка/повторен опит/null са mock-нати).
- Не проверено визуално кадър по кадър с очи; данните са от rAF извадки.
