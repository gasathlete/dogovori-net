# Оперативен списък за включване на платените продукти

Обхват: `contract_check` 2,99 €, `contract_improve` 3,99 €, `negotiation_package` 7,99 €
(с включен ДДС). Този документ НЕ съдържа стойности на тайни.

Състоянието по подразбиране е **затворено**. Включването е изрично действие на
оператора, а сървърът го налага — не интерфейсът.

## 1. Миграции (в точния ред)

```
Stage 2A база -> 0018 -> 0019 -> 0020 -> 0021 -> 0022 -> 0023 -> 0024
```

Очаквана последна приложена миграция:
`0024_product_generation_runtime_safety_correction`
(същата стойност се връща като `expected_migration` в отчета за готовност).
Резервирано за по-късно: 0025.

## 2. Задължителни тайни и флагове

| Име | Роля |
| --- | --- |
| `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` | обвързване на базата за service-only RPC |
| `LOVABLE_API_KEY` | достъп до AI Gateway (само сървърно) |
| `PRODUCT_AI_ZERO_RETENTION_VERIFIED` | `true` само след доказано нулево съхранение при доставчика |
| `PRODUCT_CHECKOUT_ENABLED` | кран за продуктовото плащане (`true` включва) |
| `PRODUCT_AI_FULFILLMENT_ENABLED` | кран за продуктовата обработка (`true` включва) |
| `STRIPE_SANDBOX_API_KEY`, `PAYMENTS_SANDBOX_WEBHOOK_SECRET` | тестово окръжение |
| `STRIPE_LIVE_API_KEY`, `PAYMENTS_LIVE_WEBHOOK_SECRET` | живо окръжение |

Всеки флаг е включен САМО при точен низ `true`. Всичко друго е затворено.

## 3. Ред на включване (първо тестово)

1. Приложете миграциите до 0024 и проверете, че отчетът за готовност връща
   `supabase_bound: true`.
2. Създайте трите еднократни цени в **тестовото** окръжение с точните сървърни
   `lookup_key` стойности, `one_time`, активни, `EUR`, суми 299/399/799 и
   поведение на данъка „включен“.
3. Регистрирайте webhook за `checkout.session.completed` (и
   `checkout.session.async_payment_succeeded`) към `payments-webhook?env=sandbox`.
4. Включете `PRODUCT_CHECKOUT_ENABLED=true` само за тестовото окръжение и
   направете една пълна тестова покупка.
5. Проверете нулевото съхранение при доставчика писмено, после
   `PRODUCT_AI_ZERO_RETENTION_VERIFIED=true` и
   `PRODUCT_AI_FULFILLMENT_ENABLED=true`.
6. Повторете 2–4 за живото окръжение и накрая включете крановете там.

## 4. Готовност на правната база

Обработката не стартира, докато няма поне един активен правен източник с
официална `https` връзка. Основание се приема само при точно съвпадение на
разпоредба, версия, източник, канонична връзка и етикет. Цитат от модела не
създава авторитет.

## 5. Проверки за пускане (smoke)

- DOCX с пълен текстов слой, до 60 000 нормализирани знака → плащането се отваря.
- Сканиран PDF без текстов слой → плащането се блокира с ясно съобщение.
- Документ, променен след плащането → резултатът се спира, не се прилага стар.
- Повторно извикване на обработката → същият резултат, без второ плащане.

## 6. Връщане назад

- `PRODUCT_CHECKOUT_ENABLED=false` спира нови плащания веднага.
- `PRODUCT_AI_FULFILLMENT_ENABLED=false` спира обработката; платените поръчки
  остават в изчакване и не се губят.
- `PRODUCT_AI_ZERO_RETENTION_VERIFIED=false` спира всяко извикване към доставчик.
