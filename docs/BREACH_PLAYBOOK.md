# Personal Data Breach Playbook (GDPR Art. 33–34)

**Owner:** DPO  •  **Version:** 2026-06-25  •  **Tooling:** `/admin/breaches` + `breach_incidents` table

## Phase 1 — Detection (T+0)
Sources: monitoring alerts, support tickets, vendor notification, external researcher (`security.txt`), staff observation.
On detection → create record in `breach_incidents` with `detected_at = now()`, `status = "open"`.

## Phase 2 — Triage (T+0 → T+24h)
- Classify category: `confidentiality` / `integrity` / `availability`.
- Estimate `affected_subjects_count` and `data_categories`.
- Assess risk to rights and freedoms (low / medium / high).
- If high → escalate to Owner immediately.

## Phase 3 — Containment & evidence
- Disable affected accounts / rotate compromised secrets.
- Snapshot logs (`audit_log`, `ai_audit_log`, edge function logs).
- Preserve `actor_id`, IP, timestamps.

## Phase 4 — KZLD notification (≤ 72h)
Required when risk to data subjects is more than negligible.
- Use admin draft template (auto-generated by `/admin/breaches` from the record).
- Submit via КЗЛД portal (https://www.cpdp.bg/).
- Record `kzld_notified_at` and `kzld_reference`.

## Phase 5 — Data subject notification (without undue delay)
Required when risk is **high**.
- Direct email to affected users via `send-transactional-email` (`templateName: "breach-notification"`).
- Public notice on /legal/changelog if direct contact infeasible.
- Record `subjects_notified_at`.

## Phase 6 — Remediation
- Root-cause analysis (use `docs/postmortem-template.md`).
- Implement permanent fix; track in `compliance_items`.
- Record `root_cause`, `remediation`, set `status = "closed"`, `closed_at = now()`.

## Phase 7 — Post-incident review
Within 30 days: tabletop walkthrough, lessons learned, policy updates if needed.

## Decision matrix

| Risk to subjects | KZLD (Art. 33) | Subjects (Art. 34) |
|---|---|---|
| None / negligible | Log internally only | No |
| Low–medium | Yes, ≤ 72 h | No (unless requested by KZLD) |
| High | Yes, ≤ 72 h | Yes, without undue delay |
