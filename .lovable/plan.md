## Цел
Приближаваме качеството на AI асистента до конкурентния сайт от снимките: (1) винаги задава 2–3 уточняващи въпроса с опции ПРЕДИ отговор на правен казус, (2) показва видима прогрес-верига (анализ → източници → преценка → генериране), (3) отговорът е дълъг, структуриран с номерирани точки и **удебелени** ключови термини, (4) след всяко правно твърдение има инлайн цитат `[чл. X, ЗЗДН]`.

## 1. Prompt reworking (`supabase/functions/assistant-chat/index.ts`)

Нов SYSTEM_PROMPT с приоритет за правни казуси (не документи):

- **Legal-Q режим (нов):** при въпрос без ясно намерение за документ (жалба/спор/казус/„какво да правя") — ЗАДЪЛЖИТЕЛНО първи ход = `ask_clarification` с 2–3 въпроса, всеки с 3–5 предопределени опции + free-text. НЕ отговаряй веднага.
- **Structured Answer Format** (задължителен след получаване на отговорите):
  1. Кратък abstract (2–3 изречения) с ключови рискове/приложим режим.
  2. Номериран списък (5–10 точки), всяка точка започва с **удебелена теза**, следва обяснение, завършва с инлайн цитат `[<КОД>, чл. N]`.
  3. Практически стъпки/съвети (bullet list, с bold ключови действия).
  4. Раздел „Кога адвокат" — 1–2 изречения.
- **Инлайн цитати:** всяко правно твърдение → цитат в квадратни скоби ВЕДНАГА след изречението. Разрешени кодове: ЗЗД, ТЗ, КТ, ГПК, НПК, НК, ЗУТ, ЗЗДН, ЗЗЛД, СК, ДОПК, GDPR, ТР № N/гггг ВКС.

## 2. Progress trace (нови SSE events)

В `assistant-chat/index.ts` преди AI повикването:

```
enqueue("progress", { step: "analyze",  label: "Анализирам въпроса" })
enqueue("progress", { step: "sources",  label: "Преценявам какви източници са необходими" })
enqueue("progress", { step: "search",   label: "Търся в нормативната база" })
// след retrieveLegalContext:
enqueue("progress", { step: "found",    label: `Намерих ${N} нормативни акта и ${M} релевантни извадки` })
enqueue("progress", { step: "rank",     label: "Преценявам кои източници са най-относими" })
enqueue("progress", { step: "generate", label: "Генерирам отговор" })
// накрая:
enqueue("progress", { step: "done",     label: "Готово" })
```

Броим `M` от `legal.chunks.length`; `N` от уникалните `short_code`. Ако имаме и таблица с реални „актове/решения" в БД — извличаме отделен count; иначе показваме `N нормативни акта и M извадки`.

## 3. Клиентски рендер на прогреса (`src/components/AssistantChat.tsx` + `DogovAIBubble.tsx`)

Нов handler за `event: progress`:
- Държим `progressSteps[]` в текущото streaming assistant съобщение.
- Рендерираме списък със ✓ (завършени), ⟳ (текущ, анимирано зелено), и приглушени бъдещи. Изчезва след като streaming завърши и текст започне да пристига (задържаме 500ms).
- Стилът: gold accent за активна стъпка (spec от 3-та снимка).

## 4. Ask-clarification UI обновление

`ClarificationCard` (в `AssistantChat.tsx`): вместо просто въпрос+текст, всеки въпрос показва бутон-опции (radio); долу „Или въведете собствен отговор…" input. При Напред — праща въпрос+избрана опция обратно като нов user message във формат:
```
1. <въпрос>
<избраната опция>

2. …
```
Точно както се вижда на снимка 2. Полетата `options[]` вече ги имаме в схемата на `ask_clarification` (ще проверим и добавим ако липсват).

## 5. Enforcement на структурата

В `intentNudges` добавяме:
- „STRUCTURED_ANSWER: след като имаш отговорите от `ask_clarification` (или ако въпросът е правен и вече си задавал уточнения), пиши отговор във формата: (1) abstract, (2) номериран списък с bold+inline цитат, (3) практически стъпки, (4) 'Кога адвокат'."
- „CITE_EVERY_CLAIM: всяко твърдение с правен ефект → `[<КОД>, чл. N]` веднага след изречението. Ако нямаш конкретен член — не измисляй, кажи 'приложим общ режим'."

## 6. Markdown цветове за цитати

В `ReactMarkdown` компонентите на assistant отговора — regex подмяна на `[XXX, чл. N]` → `<span class="text-gold font-medium">`, за да съвпада със зелените цитати от снимките.

## Технически детайли

- Файлове: `supabase/functions/assistant-chat/index.ts`, `supabase/functions/_shared/assistant-tools.ts` (ако липсват `options` в схемата), `src/components/AssistantChat.tsx`, `src/components/DogovAIBubble.tsx`.
- Backward-compatible: старите `tool_call`/`tool_result`/`meta` events остават непроменени; добавяме само нов `progress` event.
- Няма DB миграция, няма нови secrets.
